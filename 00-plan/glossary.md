| Huffman 编码（Huffman Coding） | 每次合并频率最小的两个节点来构造编码树；得到的编码是**最优前缀码** | 14.2 |
| 前缀码（Prefix Code） | 没有任何一个编码是另一个编码前缀的编码方案，可无分隔符唯一解码 | 14.2 |
| 0/1 背包（0/1 Knapsack） | 每个物品要么整个拿走、要么不拿的背包问题；**贪心的近似比无界** | 14.3 |
| 分数背包（Fractional Knapsack） | 允许把物品切分开来拿的背包问题；**按单位价值贪心即为最优解** | 14.3 |
| 近似比（Approximation Ratio） | 近似解与最优解的比值；**有界即可用，无界则无保证** | 14.3 |
| 完全背包（Unbounded Knapsack） | 每种物品可以拿任意多件的背包问题；一维写法用**正序**遍历 | 15.3 |
| 最长递增子序列（LIS） | 最长的严格递增子序列（不要求连续）；$O(n\log n)$ 解法用 tails 数组 | 15.3 |
| 伪多项式（Pseudo-polynomial） | 复杂度关于输入的**数值**而非**长度**是多项式的，如 $O(n \times cap)$ | 15.3 |
| 依赖宽度（Dependency Width） | 算 $dp[i][\dots]$ 时需要回看多少行；**决定能否压缩以及压到几维** | 15.4 |
| 滚动数组（Rolling Array） | 需要 $k$ 行时用 `dp[i % k]` 循环使用这 $k$ 行，第 $i$ 行覆盖第 $i-k$ 行 | 15.4 |
| 选型 | 按**最频繁的操作**选择数据结构，并接受它相应的代价；没有全能结构 | 16.1 |
| LRU 缓存 | 容量固定、淘汰"最久未使用"项的缓存；用**哈希表 + 双向链表**实现 $O(1)$ 的 Get/Put | 16.1 |
| 常数因子（Constant Factor） | 复杂度之外影响实际性能的部分，由**缓存、分支预测、JIT、GC** 等决定 | 16.2 |
| 预热（Warm-up） | 正式计时前先跑几遍被测代码，让 JIT 编译与缓存进入稳定状态 | 16.2 |
| 噪声区间（Noise Range） | 同一段代码多轮测量得到的 $[\min, \max]$；**区间重叠则无法区分快慢** | 16.2 |
| 动态规划（Dynamic Programming, DP） | 保存子问题的结果、避免重复计算的算法设计方法；前提是**最优子结构**与**重叠子问题** | 15.1 |
| 记忆化（Memoization） | **自顶向下**的 DP：递归 + 缓存，算之前先查表、算完把结果写进表 | 15.1 |
| 重叠子问题（Overlapping Subproblems） | 递归过程中同一个子问题被反复求解；**DP 与分治的分界线** | 15.1 |
| 状态（State） | 求解过程中**决定未来**的那一小撮信息；两个局面状态相同则后续最优解相同 | 15.2 |
| 状态转移方程（State Transition） | 描述当前状态由哪些**更小的状态**推出的式子；由「**枚举最后一步**」推导 | 15.2 |

## 单位约定

本书不涉及物理单位。性能相关一律用：
- 次数（基本操作执行了多少次）
- 倍率（相对基准实现快/慢多少倍）
- 字节（内存占用）

**不写"秒"作为结论**，除非标明具体机器与数据规模。
