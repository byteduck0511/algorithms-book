## 四、每节的写作流程（**必须严格遵守**）

**一轮 = 一节**。不要一次写多节。每节的流程是：

### 第 1 步：写代码并**实测**

在 `99-tools/samples/Ch{章号}/Sec{节号}/` 建一个控制台项目：

```
99-tools/samples/Ch13/Sec131/
  ├── Sec131.csproj      （照抄任一已有项目的模板，只改 AssemblyName/RootNamespace）
  └── Program.cs
```

**然后必须真的运行**：

```bash
"C:\Program Files\dotnet\dotnet.exe" run --project 99-tools/samples/Ch13/Sec131/Sec131.csproj -c Release
```

> ⚠️ **`dotnet` 不在 PATH 里，必须用全路径** `C:\Program Files\dotnet\dotnet.exe`
>
> ⚠️ **必须加 `-c Release`** —— Debug 模式的计时没有参考价值

### 第 2 步：核对输出

**正文里的每一段"实测输出"，都必须是从控制台复制的真实结果。**

**不要凭印象写数字** —— 我在第 6.3 节犯过这个错（正文写 `0.80 → 2.55`，实际是 `3.00`）。

### 第 3 步：写正文

路径：`chapters/ch{两位章号}/{节号}-{kebab-case-标题}.md`

**必须包含这些结构**（审校脚本会检查）：

```

**学习目标**：（用可测动词：解释/推导/编写/设计）
**先修**：
**固定术语**：
**环境与版本**：
**预计阅读**：

### 一、直觉 ...

（推导 / 例题 / 代码 / 实测输出）
### N、练习        （4–5 题，难度递增）
### N+1、练习答案   （给关键步骤，不只给结果）
### N+2、常见错误   （表格形式）
### N+3、本节总结
**下一节衔接**：
**状态外显**（```json 代码块）

## 五、必须遵守的约定

### 1. 术语必须与 `glossary.md` 完全一致

**禁止同义替换。** 比如：
- 统一用「**顶点**」，不要写成"节点"（虽然树那里用"节点"）
- 统一用「**栈顶**」「**队首**」，不要混用
- 首次出现给全称，之后可用简称

### 2. 单节字数：**1,500–6,400 字**（不是技能默认的 600–1000）

**这是经过确认的偏离**（见 `blueprint.md` 的「与技能默认值的偏离声明」）。

原因：练习答案占 35–45%，而本书的读者是**无监督自学**的工程师 —— 压缩答案等于取消自学的可行性。

### 3. 交叉引用要指向真实的节

写「详见 X.X 节」之前，确认那一节的编号正确。**审校脚本会检查悬空引用。**

### 4. 代码规范

- **泛型优先**（`MyStack<T>` 而不是 `MyStackInt`）
- **每个 `Pop`/`Dequeue` 都要清引用**（`_items[_count] = default!;`）—— 这是第 5.1 节的实测教训
- **计时实验要预热**（避免 JIT 编译开销污染）
- **测内存用 `GC.GetAllocatedBytesForCurrentThread()`**，不要用 `GC.GetTotalMemory` 差值法（第 12.1 节踩过三次坑）

### 5. 保持"实测反预期"这条主线

**这是本书区别于其他教材的核心。** 全书 63 节里有 **25 处**推翻了教科书说法的实测（见 `chapters/INDEX.md` 的汇总表）。

**遇到"实测结果和预期不符"时**：
- **不要调整数据去迎合预期**
- **要如实呈现，并解释为什么**
- 往往这就是最有教学价值的地方

### 6. 常见错误的写法

**每个坑都要注明"这是实测发现的"，而不是"理论上可能"** —— 比如：

> | 用 `GC.GetTotalMemory` 差值法测内存 | **不可靠** —— 本节实测出现 0.0 MB 和 -94.0 MB 两次假结果 |

## 八、已完成章节的"性格"（写新章节时保持一致的文风）

**每节的叙述节奏：**

1. **先给一个真实场景或类比**（"小陈遇到了一个上线事故"、"一摞盘子"）
2. **再给形式化定义**（表格 + LaTeX 公式）
3. **然后推导或逐步追踪**（用表格一步步走）
4. **接着给可运行代码 + 真实实测输出**
5. **最后用"常见错误"和"总结"收束**

**语言特点：**

- **直接**："这是本节最重要的一句话"、"这张表要横着看，也要竖着看"
- **会说"我踩过这个坑"**：很多节直接写了写作过程中的失败尝试
- **不回避反直觉的结果**：实测和理论不符时，解释原因而不是掩饰
- **每节末尾都有"下一节衔接"**：用一句话引出下一节要解决的问题
- **性能实测要给出噪声区间**（13.1 起确立）：同量级的两个实现，不能只报一个"最快值"就下结论 ——
  **要把多轮原始数字列出来**，并明确"差 1.9 倍是信号，差 20% 是噪声"

**禁止的写法：**

- 「显然」「易得」「读者很容易看出」这类跳步用语
- 只给结论不给推导
- 练习没有答案，或答案只给结果
- 把"理论上的可能性"当成"实测发现"来写

## 九、成品形态与构建（2026-09-18 补）

写作之外，"把书变成可读的成品"这一层也做完了。三种形态三种构建方式：

| 形态 | 命令 | 产物 |
|---|---|---|
| 网页版 | `npm run build` | `_book/`（静态站点，可部署） |
| EPUB | `powershell -File 99-tools\build-ebook.ps1` | `_ebook/algorithms-book.epub` |
| PDF | 同上（一条命令出两种） | `_ebook/algorithms-book.pdf` |

### 网页版：两个默认插件不能用，已自建

- **`zh-search`** —— HonKit 默认的 lunr 对中文不可用。它按空白分词，中文整段变成一个 token，索引里只剩 **910 个单字**；且索引经 `JSON.stringify`/`load` 后内部结构不一致，`lunr.js:1150` 的 `tokenStore.get(token)[ref].tf` 读到 undefined，**搜「递归」会让搜索框抛异常**。原索引 **14.32 MB**。
  改为中文 **2-gram** 分词 + 剔除 `<pre>`（代码块，状态卡也在其中）后：**1.83 MB（-87%）**，搜「递归」26 条命中、首位 2.1 节。

- **`zh-katex`** —— HonKit 不带数学渲染，**3,566 个行内公式 + 252 个块级公式**原本全是裸 LaTeX。
  注意：**不要用 `honkit-plugin-katex`**。它走 GitBook blocks，在 Markdown 解析**之前**把 `$...$` 短路成模板标签，是全局配对；而本书 **44 节**含 C# 插值字符串（`$"{"n",8} | ..."`），代码里那些孤立 `$` 会打乱配对，构建直接报 `unknown block tag: endmath_inline` 失败。改正文转义 `$` 不可行（约定是代码可复制运行）。
  本插件改为**前端渲染**，用 auto-render 并设 `ignoredTags: ['pre','code',...]`，代码块天然免疫。

> ⚠️ **改插件源码后必须重跑 `npm install`** —— `file:` 依赖是复制不是符号链接。
>
> ⚠️ **`book.json` 千万不要写进 `.bookignore`** —— HonKit 用该文件过滤扫描到的文件清单，`book.json` 一旦被滤掉，配置整个读不到、**静默回退默认配置**：插件退回内置 lunr（中文搜索与 KaTeX 双双失效）、`structure.readme` 退回 `README.md`（首页变成 README，还多出一个 `intro.html`）。这个坑踩过一次。

### 电子书：四个坑

1. **PDF 不走 LaTeX。** 机器上 xelatex/lualatex/pdflatex/tectonic **全无**，而全书 3,818 个公式；装 TeX Live 是几 GB 的事。改用 `pandoc --mathml` 出 HTML + **Edge headless `--print-to-pdf`**（Chromium 自带 MathML Core 渲染），完全离线。

2. **引号方向会反。** 源文件通篇英文直引号 `"`（14,945 个），pandoc 的 smart 按**英文**规则判开合：引号前是空白/开括号才算开引号。中文没有空格，`个"重复"` 的引号前面是汉字，被判成闭引号 → `个”重复”`。修法：`build_ebook.py` 里自行转换（跳过代码围栏与行内代码），并给 pandoc 加 `-smart`。

3. **列表会被压成一行。** pandoc 的 markdown 默认**要求列表前有空行**，而每节「学习目标」「先修」后面直接跟 `- ` 列表（honkit 认得，pandoc 不认）。需要 `+lists_without_preceding_blankline`。

4. **「状态外显」不是成书内容。** 它是给写作/审校流程用的元数据，`build_ebook.py` 整块剥离（63 处）。

另外 `print.css` 里 **`pre` 不要设 `page-break-inside: avoid`** —— 本书代码块普遍 40~80 行，超过一页时无法避开，浏览器只能整块推到下一页，每页底部留下大片空白。

### 顺带修掉的内容缺陷

第 **13、14、15、16** 章的第一节缺少 `# 第 N 章` 标题和「本章解决的问题」引言（其余 12 章都有）。已按既有格式补齐 —— 这四章是后期写的，漏掉了。缺标题会让 EPUB/PDF 少 4 个分章点，网页版正文也没有章标题。
